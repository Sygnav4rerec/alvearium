How the fundamental is computed
  1. Every glyph is embedded as a point in a 16-dimensional relational space. Its coordinates come from hashing the glyph (SHA-256, expanded to 256 bytes) through a fixed random projection — a "relational fingerprint," not a lookup table.
  2. Each glyph's position is then blended with the glyphs that came before it in the string (a causal context window of radius 3), so the same glyph lands in a different place in the space depending on what precedes it. A lone "A" carries no relational content until something follows it.
  3. The string becomes a trajectory through this space. The engine measures its mean velocity (how far each step moves) and mean jerk (how sharply the direction changes) — the string's relational "energy" and "tension."
  4. A positional drift term — later glyphs pulling the path's centroid — is added so that reordering the same glyphs (e.g. "hive" vs "evih") changes the outcome, not just which glyphs are present.
  5. The combined value is compressed with tanh and mapped exponentially onto 40–2000 Hz, so the result is always a single clean, audible pure tone.

This is an interpretive framework built for the hive's own practice, not a scientific or medical claim about sound. It runs entirely in your browser — nothing about your glyph string is sent anywhere.
